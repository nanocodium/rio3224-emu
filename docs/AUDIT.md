# Rio3224-D2 emulation audit

Status of every subsystem against the "complete functional emulation" specification. REAL = the behaviour
comes from the real firmware or from an implemented model that carries actual data; PARTIAL = control side
real, data side missing or approximated; FAKE = decorative/animated (must be removed); MISSING = not there.
Updated as work proceeds; the goal is zero FAKE runtime subsystems.

Architecture note. This emulator runs the unmodified Rio3224-D2 host firmware (`RIO2_PROG.BIN`) on an
emulated SH-2A board. Everything the host MCU does on the real unit is therefore real here: the parameter
tree (32 input channels x {HA gain, +48V, HPF on/frequency, GC on/start gain}), the front-panel menus,
encoder/button handling, panel lock, start-up modes (REFRESH / RESUME), persistence in flash, factory
initialisation scopes, the error/message system (E00-xx / E01-xx), unit ID, the Dante module control
protocol, R Remote's network server, the console HA-remote bridge on the module's second UART. What the
host MCU does *not* do is audio: on the real unit audio lives in the head-amp FPGAs (analog PGA + ADC), the
DSP (fine gain, HPF, gain compensation, metering, output routing, DAC/AES feeds) and the Dante module
(PCM transport). Those are the parts the audio engine has to provide, driven by the firmware's own writes
(SCIF1 head-amp frames, CS4 DSP coefficient registers) and feeding its meter port back.

Fake-implementation search (spec item 82): no random/animated meters, no `Math.random`, no placeholder
audio paths exist in `emu/` (the audio path simply does not exist yet). Test-only code: `--dante-clock-ms`
scripted clock, `--press`, `--console-script`, `tools/*` scripts.

Long-run (spec item 79): `tools/long-run-audio.sh` ran the unit for 10 minutes of emulated time with 32 tones and a
full TX -> RX loop; every minute's meters read -50.0 dBFS on all 32 inputs, the TX capture of the last seconds is
clean, no Dante block was lost, the DIO stayed locked and the firmware reported no error (260 s wall).

Not understood / not implemented, stated plainly: ARC 0x4100 (start code 0x280f) unanswered; 0x1100 / 0x1102 answered with zeros (accepted); the 0x1003 string layout differs from Virtual Soundcard's; multicast TX flows, AES67, device lock, Dante Domain Manager, redundant audio: absent. The implementation is a Controller-interoperable virtual endpoint, not a certified Dante device.
